# AI 활용 가이드: 직접 할 것과 맡길 것

**원칙**: 이해해야 하는 것은 직접 하고, 이해와 상관없는 반복 작업은 AI에게 맡긴다.

판단 기준이 헷갈리면 이렇게 물어본다.
> "이걸 AI가 대신 해주면, 내가 배워야 할 걸 못 배우게 되나?"
> → 그렇다면 직접 한다.

---

## 표시 기호

[learning_plan.md](learning_plan.md)의 모든 항목에 아래 기호를 붙여 두었다.

| 기호 | 의미 | AI 사용 방법 |
|---|---|---|
| 🖐 | **직접** | 코드를 받지 않는다. 다 짠 뒤 리뷰만 받는다 |
| 🤝 | **먼저 직접, 막히면 AI** | 30분 이상 막히면 힌트를 단계별로 받는다 |
| 🤖 | **AI에게 맡김** | 바로 맡겨도 된다. 결과물이 무엇을 하는지만 이해한다 |

## 🖐 직접 해야 하는 것

이 공부의 본체다. AI가 대신하면 공부한 게 아니다.

- **핵심 알고리즘 구현**: MLP → PyTorch 이식, CNN 학습 루프, REINFORCE, DQN, PPO, 셀프플레이
- **손실 함수와 업데이트 식**: 왜 이 식인지 종이에 써 보기
  - 예: REINFORCE의 `loss = -log_prob * return`에서 왜 마이너스가 붙는지
- **디버깅 첫 30분**: 학습이 안 될 때 원인을 먼저 스스로 추측하고 확인해 보기
- **하이퍼파라미터 실험**: 학습률, 할인율 등을 바꿔 보고 결과 비교하기
- **개념 정리 노트**(`notes.md`), **논문 요약**, **작업 기록**(`worklog.md`): 내 말로 써야 내 것이 된다

## 🤝 먼저 직접 하고, 막히면 AI

- **개념 질문**: 책이나 강의를 먼저 보고, 이해가 안 되는 부분만 질문하기
- **에러 해결**: 에러 메시지를 직접 읽고 검색해 본 뒤, 그래도 안 되면 질문하기
- **코드 리뷰**: 다 짠 코드를 보여주고 "틀린 곳, 더 나은 방법"을 묻기
- **결과 해석**: 학습 그래프를 보고 내 해석을 먼저 말한 뒤 맞는지 확인받기

## 🤖 AI에게 맡겨도 되는 것

공부 목표와 상관없는 작업이다. 여기에 시간을 쓰지 않는다.

- 가상환경, PyTorch/CUDA 설치, 패키지 충돌 해결
- 스타크래프트 II 설치, 맵 파일 배치, PySC2/SMAC 설정
- 학습 그래프 그리기(matplotlib), 로그 저장, 모델 저장/불러오기 코드
- 데이터 다운로드, DataLoader 같은 반복 코드
- git 사용, 폴더 구조 정리
- 라이브러리 API 찾기 (예: "python-sc2에서 건물 짓는 함수가 뭐야?")

## 막혔을 때: 힌트 단계

🤝 항목에서 막히면 한 번에 답을 받지 말고 한 단계씩 올린다.

1. **개념 힌트**: "어떤 개념을 다시 봐야 해?"
2. **방향 힌트**: "내 코드에서 어느 부분이 문제야? 고치지는 말고 위치만"
3. **의사코드**: "의사코드로만 보여줘"
4. **부분 코드**: "이 함수 하나만 보여줘"

4단계까지 갔다면 받은 코드를 지우고 **다음 날 보지 않고 다시 짜 본다.**

## AI에게 요청할 때 쓰는 말

| 이렇게 말하면 | AI는 이렇게 한다 |
|---|---|
| "힌트만 줘" | 코드 없이 방향만 알려준다 |
| "리뷰만 해줘" | 코드는 고치지 않고 문제점만 짚는다 |
| "설명만 해줘" | 개념을 설명하고 코드는 주지 않는다 |
| "이건 맡길게" | 🤖 항목으로 보고 직접 처리한다 |

## 자기 점검 규칙

- AI가 준 코드는 **한 줄씩 설명할 수 있을 때만** 쓴다.
- 🖐 항목을 끝낸 뒤 스스로 물어보기: "이 코드를 처음부터 다시 짤 수 있나?"
- 작업 기록에 AI 도움을 받은 부분을 적는다. (예: "PPO clip 부분 힌트 2단계까지 받음")
